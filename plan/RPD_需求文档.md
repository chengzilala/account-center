## 1 项目概述

- **产品定位**：全站统一的**身份层**。回答两件事——「你是谁」「你能进哪个作品」。
- **不做**：不做业务后端，不存第三方 Key，不合并各作品的数据。
- **目标用户**：Chester 自己（管理侧）+ 各作品的用户（登录侧）。
- **一句话**：一张身份证 + 一张门禁卡；各店铺里买过什么、存了什么，仍归各店。
- **当前状态**：需求 + 两份契约 + **后端核心（29 个 action / JSON 存储 / SMTP 发信 / 35 项自动化测试）** + **前端五页（登录 / 扫码确认 / 我的账户 / 用户协议 / 隐私政策）** + **作品侧 SDK 与跨域登录票据（含静默登录）** 已完成；**线上已部署（`https://account.chesterlee.cn`，2026-10-28）**。

## 3 详细功能需求

### 3.1 身份模型（P0）

- `uid` = 人，全局唯一，所有作品只认它。
- 钥匙：`email` / `phone`（手机号）/ `deviceId`（原微信悦读 32 位账户码）/ `oauth:<平台>:<平台用户 ID>` / `openid` / 6 位临时码。
- 规则：一个 uid 可有多把钥匙；一把钥匙只属于一个 uid；绑定冲突只提示、不自动合并。

### 3.2 登录（P0）

| 方式 | 流程 | 状态 / 约束 |
|---|---|---|
| 邮箱验证码 | 输入邮箱 → 收 6 位码 → 验证 → 查/建 `email:<邮箱>` → 建会话 | 已可用；限流、有效期短 |
| 账户码 | 粘贴 32 位码 → 校验 → 查/建 `device:<码>` → 建会话 | 已可用；视同密码：严格限流、失败锁定 |
| 6 位码 | 已登录设备生成 → 另一台输入 → 换 uid 并建会话 | 已可用；10 分钟、一次性 |
| 手机扫码 | 电脑登录页出二维码（`qr.html?c=<qrId>`）→ 已登录手机扫码点「确认」→ 电脑轮询拿到 Token 自动登录 | 已可用；2 分钟有效、一次性；手机端必须已登录；拒绝 / 过期都拿不到 Token |
| GitHub / Gitee / Microsoft | 授权页回跳 → 校验 state → code 换用户 ID → 查/建 `oauth:<平台>:<id>` → 一次性 code 换 Token | 已可用；只显示已配置 Client ID/Secret 的平台；回调 `GET /oauth/<平台>/callback` |
| 手机号验证码 | 输入手机号 → 过图形验证码 → 收短信码 → 验证 → 查/建 `phone:<11 位>` → 建会话 | 已可用（阿里云短信认证）；发送前必须有图形验证码；同号 1 次/分钟、5 次/小时、10 次/天；10 分钟有效 |
| 小程序 openid | 云函数从上下文取 openid → 查/建 `wx:<openid>` | P1；个人小程序不能用 web-view |
| 微信 / Google | 第三方授权回调 → 平台账户标识 → 查/绑 `oauth:<平台>:<id>` → 建会话 | P1 预留：**页面不展示**，等平台应用与回调域名就绪再上 |

**第三方登录的账户合并规则（方案 A）**：第三方登录只作为「登录方式」，不自动合并账户。
若第三方返回的已验证邮箱已在本站注册，回调直接提示「请先用邮箱登录，再到登录方式里绑定」，不建新号；
已登录用户可在「我的账户 → 登录方式 → 添加登录方式」主动绑定；一把第三方钥匙只能属于一个 uid，冲突提示不抢钥匙。

> 未接入的方式**不在页面上出现**（没有入口、没有灰按钮、没有「敬请期待」），只在文档与本表里预留；配置完成后复用同一套「钥匙 → uid → 会话」流程，不改变身份模型。

### 3.3 我的账户与会话（P0）

- 展示：昵称（可就地编辑，1–20 字）、头像（点头像或「换头像」上传，客户端压成 160×160 JPEG，服务端上限 48KB）、邮箱 / 手机号掩码、已绑定钥匙、我的作品。
- 默认形象：**没自定义昵称 / 头像的账户，由系统按 uid 生成一套默认昵称（如「半糖的海豚」）与默认头像（渐变色块 + 大 emoji，SVG 图片），存进账户资料**；同一 uid 每次看到都一样，用户改了昵称 / 换过头像后不再覆盖；老账户在下次读取资料（`me`）时自动补齐。
- 动作：退出当前设备、退出全部设备、注销账户（二次确认，审计留痕）。
- 登录方式管理：邮箱 / 手机号 / 账户码 / 第三方统一列在「登录方式」；手机号与第三方支持在账户页主动绑定，绑定前同样要过图形验证码；已绑定的钥匙可解绑，但至少保留一种。
- 账户凭证：在「我的账户」生成一张图片（完整邮箱、昵称、uid、注册 / 生成时间 + 二维码），支持系统分享保存到相册或下载；**只放完整邮箱，不放完整账户码**。
- 凭证二维码：内容为 `https://account.chesterlee.cn/login.html?e=<邮箱>`，扫码即打开账户中心登录页、自动切到邮箱面板并填好邮箱；二维码在前端本地生成（`web/assets/qrcode.js`，零依赖，按长度自动选 V3–V6），不经过第三方服务。

### 3.4 管理后台（P1）

- 用户列表、强制下线、审计日志查看；仅 `admin` uid 可进（首个 admin 手动写进配置，不走注册）。

### 3.5 作品接入（已落地 2026-10-27）

- 作品侧引入 `sdk/ps-auth.js`，用 `init / getUser / requireLogin / logout / track`，不直接写接口地址。
- 跨域登录**不用共享 Cookie**：作品页跳账户中心登录 → 登录页签 5 分钟一次性票据 → 回跳作品 → SDK 自动换 30 天 Token 并立刻从地址栏抹掉 `ps_ticket`。
- 票据只发给已登记作品域名（`ac_products.url`）或 `ALLOWED_ORIGINS` 白名单，防开放跳转。
- 已有作品接入：`personal-site`（顶栏「登录 / 我的」+ 作品卡「打开作品」上报）——用 `tools/register-product.js` 登记作品。

### 3.6 我的足迹 · 行为记录（已移除，2026-10-28）

> **2026-10-28 决定移除**：用户反馈「足迹看不出有啥用」，账户页整块删除，作品侧 `PSAuth.track` 调用同步停用；`me.activity` / `me.activity.clear` 接口与 90 天清理逻辑保留（后续若要「最近使用」可直接复用）。
> 以下为原设计，仅作历史留档。原确认（2026-10-26）：记录四类行为；展示在账户页「我的足迹」区块；留存 90 天，浏览类可自助清除。

**3.6.1 记录范围**

| 类型 | 事件举例 | 来源 | 本人可见 | 可清除 |
|---|---|---|---|---|
| 账户动作 | 邮箱登录、账户码登录、6 位码登录、退出当前 / 退出全部、绑定 / 解绑钥匙、生成 6 位码、生成凭证、注销 | 账户中心自记 | 是 | 否（留痕） |
| 作品使用 | 打开某作品、使用某核心功能（如「生成阅读人格」「同步跑步数据」） | 作品调 SDK 上报 | 是 | 是 |
| 页面浏览 | 访问 `account.html` / 作品内页面 | 账户中心自记 + 作品上报 | 是 | 是 |
| 安全事件 | 登录失败、新设备登录、限流 / 锁定 | 账户中心自记 | 是（简要版，不显示 IP 明文） | 否 |

**3.6.2 展示**

- 位置：`account.html`「我的作品」之后、「跨设备登录」之前，新增「我的足迹」卡片。
- 默认最近 10 条、时间倒序；每条 = 类型标签（账户 / 作品 / 浏览 / 安全）+ 标题 + 平台（网页 / H5 / 小程序 / 插件）+ 时间（今天只显示时分，跨天显示日期）。
- 筛选：全部 / 登录与安全 / 作品 / 浏览（前端切换，不重复请求）。
- 「查看全部」展开到 50 条，底部「加载更多」按 `cursor` 翻页。
- 空态：「还没有行为记录」。
- 底部：「清除浏览记录」按钮（二次确认）；安全类不提供删除入口。
- 隐私提示：「只有你自己能看到这些记录；90 天后自动删除。」

**3.6.3 留存与清除**

- 保留 90 天：服务启动时 + 每日一次清理过期事件。
- 用户清除：`scope = product / browse` 可清；`scope = account / security` 不清除（与审计口径一致）。
- 浏览去重：同一 uid + 同一作品 + 同一页面，30 分钟内只记 1 条，避免刷屏和体积膨胀。

**3.6.4 接口（已同步到《接入契约》v0.3）**

| action | 入参 | 说明 |
|---|---|---|
| `track`（需登录） | `productId` / `event`（`open` / `use` / `browse`）/ `title` / `platform` / `meta` | 作品侧上报；同 uid 60 条/分钟限流；`event` 走白名单，未知直接忽略（`action` 固定为 `track`，不能复用） |
| `me.activity`（需登录） | `range`（7d/30d/90d）、`scope`、`cursor`、`limit`（≤50） | 只返回本人事件，字段脱敏 |
| `me.activity.clear`（需登录） | `scope: product / browse` | 删除本人对应记录，并写一条审计 |

**3.6.5 边界与假设**

- 只记「做了什么」，不记业务内容（读了哪本书、跑了哪条路线仍留在作品内）。
- 第三方 Key、Token、验证码、完整账户码一律不入事件表。
- IP 只存哈希、不存明文；UA 只归并为设备类型（手机 / 桌面）。
- 未登录时的页面访问（如首次打开 `login.html`）**不记录**——没有 uid，也不该追踪匿名浏览；登录成功后从登录页开始记。
- 假设：首期只有个人官网 + 微信悦读接入上报；未接入的作品不会出现在「作品」类记录里。

## 4 UI / UX 要点

- 页面：`login.html`（登录）/ `account.html`（我的账户）/ `terms.html`（用户协议）/ `privacy.html`（隐私政策）/ `admin.html`（管理后台，P1）。
- 风格（2026-10-26 改版）：纸张底色 `#f2f0e9`、黑色细线分区、大字号标题、红色 eyebrow 小字；卡片直角、无圆角，登录页左文右卡。
- 换肤（2026-10-28 新增）：**结构 / 流程 / 字段完全不变，只换配色**。默认浅色；主体是黑色的作品登记成 `dark` 后，登录页 / 账户页 / 协议页自动同色。配色只在**账户中心登记一次**（`register-product.js` 的 `[light|dark] [#rrggbb]`），作品代码零改动；临时预览可用 `?theme=dark&accent=%23rrggbb` 覆盖。主题存本机，登录后进「我的账户」自动沿用。
- 登录页：只列出已可用的方式——邮箱验证码（主按钮）+ 已配置的 GitHub / Gitee / Microsoft + 账户码 / 6 位码入口；**未配置 Client ID 的平台与短信不出现**；底部固定「用户协议 / 隐私政策」同意文案。
- 邮箱自动补全（2026-10-30 新增）：邮箱登录输入框按已输入内容补全常用后缀（qq.com / 163.com / 126.com / gmail.com / outlook.com / foxmail.com / icloud.com / hotmail.com / sina.com / yahoo.com）；支持 ↑↓ 选择、Enter 填入、Esc 关闭、鼠标点选，填入后自动收起；纯前端本地计算，不发请求、不记录输入内容。
- 登录方式图标化（2026-10-28）：主按钮带线性图标；第三方登录保持整行按钮（前缀图标）；账户码 / 6 位码等次要方式改为**图标格**（图标在上、文字在下），不再用文字链接。
- 我的账户：账户状态（创建时间、uid、生成凭证）+ 登录方式（邮箱 / 手机号 / 账户码 / 已启用第三方逐项标注已连接 / 未连接，可连接与解绑；账户码未绑定时「连接」＝服务端生成，已绑定时「连接」＝重置，新码只显示一次）+ 我的装置（CSS 绘制的封面网格，超过 5 个可展开）+ 跨设备 6 位码 + 隐私与安全（协议入口、退出全部、注销）。
- 协议页：用户协议与隐私政策各自独立，隐私页含「我们怎么保护账户」锚点 `#security`；两页与登录页、账户页互链。
- CSS 类名前缀 `ac-`；纯静态、零构建、零外部框架、无外部图片依赖。
- 文案直白：「用邮箱登录」「在另一台设备输入这 6 位数字」。
- 「我的足迹」沿用卡片样式：一张卡片内完成「列表 + 筛选 + 查看全部 + 清除」，不新开页面（待开发）。

## 5 技术方案（摘要）

| 层 | 方案 |
|---|---|
| 代码 | 独立项目 `account-center`，独立仓库、独立版本 |
| 运行 | **与奶茶项目同台腾讯云轻量服务器**（2026-10-25 改定）；单机常驻 Node 进程，只用 `ac_*` 数据，不碰微信悦读 `wre_*` 与高驰任何集合 |
| 访问 | 页面与接口同机：Nginx/Caddy 反代 + HTTPS；域名待定（首选 `account.chesterlee.cn`，未定前先用 IP / 现有域名跑通） |
| 接口 | 单进程 `server.js`（`POST /accountCenter`，按 `action` 路由；`GET /healthz` 健康检查）；统一 JSON |
| 数据 | 首期本地 JSON 文件（`lib/store-json.js`，单机单进程）；集合口径不变：7 个 `ac_*` |
| 行为记录 | **复用 `ac_audit_logs` 扩展**（新增 `scope` / `source` / `platform` / `visibleToUser`），不新增第 8 个集合；启动 + 每日清理 90 天前事件；量大后随存储一起换 SQLite |
| 邮件 | **自建 SMTP**（nodemailer；`SMTP_HOST/PORT/SECURE/USER/PASS` + `MAIL_FROM`），不用 CloudBase |
| 资源占用 | Node 常驻约 50–100MB 内存、CPU 基本空闲；2 核 2G 与奶茶同台足够（瓶颈是邮件发送频率与磁盘，不是账户中心） |

## 7 成功标准

1. 一个邮箱和一个 deviceId 能落到**同一个 uid**。
2. 老用户首次登录绑定后，微信悦读数据不丢、插件同步照常。
3. 从官网能进账户中心并顺利返回。
4. 账号泄露路径可控：账户码限流 + 失败锁定，6 位码一次性短时有效。
5. 登录、退出、生成凭证等账户动作发生后，刷新「我的足迹」能看到对应记录。
6. 作品接入上报后，足迹显示作品名与动作；同一页面 30 分钟内不重复出现。
7. 点「清除浏览记录」后，浏览 / 作品类记录立即消失，安全类保留。
8. 超过 90 天的记录自动清理，数据文件不无限增长。

## 8 风险与应对（摘要）

| 风险 | 应对 |
|---|---|
| 复用环境耦合 | `ac_*` 独立集合 + 独立云函数 + 接口契约，随时可导出迁移 |
| 账户码等于密码 | HTTPS、严格限流、失败锁定 |
| 邮件进垃圾箱 | 正规发件通道 + 重发 / 换邮箱 |
| 旧数据迁移 | 惰性迁移，首次登录才绑，保留旧入口 |
| 同一钥匙绑两个 uid | 绑定前查冲突，首期只提示 |
| 行为记录体积膨胀 | 30 分钟同页去重 + 90 天自动清理；量大换 SQLite |
| 行为记录泄露 / 越权 | 只返回本人事件；IP 只存哈希；不存 Key / Token / 业务内容 |
| 作品伪造或刷量上报 | `track` 必须带登录 Token + 同 uid 限流 + `action` 白名单 |

## 9 已确认决策

1. 项目位置：`Coding/account-center/`（已按此初始化）
2. 运行环境：**与奶茶项目同台腾讯云轻量服务器**（2026-10-25 改定；原「首期新开独立 CloudBase 环境」作废）
3. 域名：先用服务器 IP / 现有域名跑通，再绑 `account.chesterlee.cn`（同机反代，代码不变只换域名）
4. 邮件通道：**自建 SMTP**（nodemailer；`SMTP_HOST/PORT/SECURE/USER/PASS` + `MAIL_FROM`）；原「CloudBase 自带邮箱验证码」作废
5. 存储：首期单机 JSON 文件，单进程；用户量上来再换 SQLite（存储适配器可替换）
6. 为什么不用 CloudBase：免费体验版 2025 年起不含静态网站托管，自定义域名需个人版 + 备案（免费环境不支持备案）；且奶茶项目已必须开服务器
7. 容量结论：2 核 2G 可同时跑账户中心 + 奶茶；腾讯云控制台「升配」改套餐即可（通常需关机重启几分钟），带宽、数据盘可单独加
8. 账户凭证卡（2026-10-26 新增）：只放**完整邮箱 + uid + 昵称 + 时间**，**不放完整账户码**；图片由前端 Canvas 生成，手机可分享保存到相册，桌面可下载
9. 行为记录（2026-10-26 新增）：范围 = 账户动作 + 作品使用 + 页面浏览 + 安全事件；展示 = 账户页「我的足迹」区块（不新开页面）；留存 90 天，浏览 / 作品类可自助清除，账户 / 安全类不可清
10. 行为记录存储：首期**复用 `ac_audit_logs` 扩展**为统一事件表（保持 7 个 `ac_*` 不变），不新增集合；单文件体积过大时随整体存储换 SQLite
11. 账户页视觉改版（2026-10-26）：按参考图改为「纸张底色 + 黑色细线 + 大标题」编辑风；页面固定为登录 / 我的账户 / 用户协议 / 隐私政策四类，协议与隐私互链
12. 多登录方式（2026-10-26，同日修订）：页面只展示已可用的邮箱 / 账户码 / 6 位码；微信 / Google / GitHub / Microsoft / 短信**不在页面出现**，仅在本文 §3.2、[接入契约](接入契约.md) §4.15、[统一账户规范](统一账户规范.md) §4 预留为 P1，等平台应用、回调域名、短信服务商就绪再接入
13. `track` 的字段命名（2026-10-27）：`action` 已被用于选路由（固定 `track`），行为类型改用 `event`（`open` / `use` / `browse`），避免同名字段冲突
14. 登录样式可调（2026-10-28）：账户中心只维护**一套结构 + 多套配色变量**；每个作品在账户中心登记一次配色（`product.theme`），所有登录入口自动同色，不各自复制登录页、不改登录与账户流程
15. 昵称编辑（2026-10-28 新增）：账户页昵称旁加「编辑」就地改昵称（1–20 字，去首尾空白），保存即时刷新昵称与头像首字；**只开放昵称**，邮箱与 uid 是登录钥匙不在此改；接口 `account.profile`
16. 凭证二维码（2026-10-28 新增）：二维码放**登录链接**（`login.html?e=<邮箱>`），不直接放账户码；扫码后由登录页识别 `e` 参数自动切到邮箱面板并预填，验证码仍需用户自己收；本地生成、不请求第三方二维码服务
17. 第三方登录（2026-10-28 新增）：接入 **GitHub / Gitee / Microsoft**，采用**方案 A**——只做登录方式与主动绑定，不自动合并账户。第三方已验证邮箱若已注册，提示先用邮箱登录再绑定；已登录用户在账户页可绑定。密钥只放服务端环境变量，回调走 `GET /oauth/<平台>/callback`，页面只拿一次性 code 换 Token。微信 / Google / 短信仍为 P1，不展示入口
18. 登录方式总览与解绑（2026-10-29 新增）：账户页「登录方式」区固定列出**邮箱 / 账户码 / 已启用的第三方**，逐行在右侧标绿色「已连接」/ 灰色「未连接」；已绑定的可点「解绑」（二次确认），第三方未绑定的直接给绿色「连接」入口。**至少保留一种登录方式**，只剩一种时解绑按钮禁用、接口回 `LAST_KEY`；解绑只删该钥匙，不删 uid、不影响其他方式与登录态
19. 手机号验证码登录（2026-10-29 新增）：走阿里云「短信认证」（系统预置签名 + 模板，个人实名可用，核验免费、0.06 元/条起），不做自建签名与模板审核。手机号与邮箱**独立建号**，老用户需在账户页「登录方式」主动绑定，不自动合并；绑定冲突回 `PHONE_TAKEN`。发送短信前必须先过图形验证码（自研 SVG 点阵），再叠加手机号 / IP 多级限流。`ALIYUN_SMS_*` 未配齐时整条链路自动隐藏，其他登录不受影响
20. 默认昵称与头像（2026-10-30 新增，2026-11-04 调整头像风格）：没自定义的账户**不做空白占位**，由系统按 uid 生成「形容词 + 小动物 / 自然物」的默认昵称（如「戴围巾的企鹅」）和「纸底 + 墨线 + 一个色块」的**简笔画人像** SVG 头像，读取资料（`me`）时补齐并落库；同一 uid 永久一致，用户自定义后不再覆盖。生成规则在服务端（`lib/persona.js`），各作品通过 `me` / SDK 自动拿到，无需改作品代码
21. 账户码在账户页生成（2026-10-30 新增）：账户码不再是「只有微信悦读老用户才有」的遗留钥匙——账户页「登录方式 · 账户码」未绑定时给「连接」按钮，点击后由**服务端生成** 32 位码并**只展示这一次**（可复制，提示等同密码）；已有时点「连接」= 重置，**旧码立即失效**；已绑定则照常显示掩码 + 解绑。接口 `account.code.generate`。生成后可在登录页「账户码登录」粘贴使用
22. 昵称 / 头像参考（2026-11-04 新增）：改昵称与换头像时不再让用户干想——点「编辑」在输入框下方给出 12 个候选昵称，点选即填入；点「换头像」弹出 12 个系统画的简笔画头像供挑选，也保留「上传自己的图片」。候选来自服务端候选池（`ac_persona_pool`，首次使用时一次性生成 60 个昵称 + 60 个头像并落库，之后每次只从中抽 12 个，不再重复生成，接口 `account.persona.options`；每页只取一次），**只有用户点选后才通过 `account.profile` 落库**，各作品读到的就是选中的那一套
